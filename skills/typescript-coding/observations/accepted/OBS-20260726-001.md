## Context (input)

Same defect family as `skills/python-coding/observations/accepted/OBS-20260726-001.md`, transferred a
second time onto `typescript-coding` because the gap is a property of test construction, not of any one
language's standard library or type system. The original nine occurrences were found in a Python
consumer build (`news-intel-docs`, RM-TASK-016, agent-plane observability skeleton); the mechanism
that produced them — a test's case set, subject, or dimensional coverage chosen from the artifact under
test rather than the specification — reproduces identically in TypeScript: `as const` registries stand
in for Python's implicit enumerations, layered defence is just as common across an upstream filter and a
downstream serializer, and `Map`/discriminated-union dispatch reproduces the raw-vs-normalized-key and
missing-arm failure modes exactly.

`skills/typescript-coding/references/testing.md` §Hygiene already carries the general "do not tune a
test to the gate" rule and does not reach any of the three sub-patterns below, exactly as documented for
`python-coding@1.1.0` before its fix — confirmed by inspection: neither "provenance", "layered", "outer
layer", nor "dimension" appears anywhere in the pre-change file.

## Expected behavior

Three rules, one family — *a test's cases, its subject, and its dimensions are all chosen from the
specification, never from the artifact under test*:

1. **Provenance of the case set.** A test's case set is derived from the *specification's* class, never
   copied from — or parametrized over — the artifact under test. A healthy mutation score is not
   evidence of specification coverage: when the case set mutates together with the implementation, the
   mutant is killed and the unmet specification stays invisible.
2. **Subject of the test under layered protection.** When a property is protected by more than one
   layer, a test that reaches it through the **outer** layer proves nothing about the inner one; a
   defence-in-depth claim is unverified until each layer is exercised on a path where it is the
   **only** protection. Equivalently: every layer needs a test that goes red when that layer alone is
   deleted.
3. **Totality of the case set across the dimensions the control discriminates on.** A parametrized set
   that varies **one** dimension of the input says nothing about the others, and its size is not
   evidence. Where the implementation carries a dedicated mechanism for another dimension (a
   raw-vs-normalized key form, an exhaustive `switch` arm over a discriminated union's discriminant),
   that mechanism is by construction untested until the case set varies that dimension too. Operational
   form: for each guard, name the dimensions of the input it discriminates on, and require at least one
   case per dimension — a surviving mutation is evidence of a missing **dimension**, not merely a
   missing case.

## Actual behavior

`skills/typescript-coding/references/testing.md` §Hygiene, pre-change, has no clause reaching any of the
three patterns above; its nearest rule ("do not tune a test to the gate") is explicitly a distinct
pattern (hardcoding an expected value), not this one.

## Minimal reproduction

Three deterministic, project-independent, self-contained TypeScript reproductions — one per rule:

**Rule 1 (provenance):** `const ALLOWED = ['a', 'b', 'c'] as const;` for a rule the specification
states as an open class; `it.each(ALLOWED)(...)` parametrized over that same array (or a test that
imports the derived union type instead of the specification). Mutating the array
(`['a', 'b', 'cc']`) turns the test red — a healthy mutation score — while one specification-class
member `d` is silently unhandled and no test notices. Stricter variant: if the test imports the array
rather than copying a literal, the mutation does not even fail.

**Rule 2 (layered subject):** a value cleared both by an upstream filter keyed on field name and by an
unconditional downstream overwrite in the serializer; one test injects the value through the filtered
channel and asserts it is absent from the output. Deleting the downstream overwrite alone leaves the
suite green, because the upstream filter already intercepts the value first.

**Rule 3 (dimensional totality):** a `Map` whose keys are normalized by a dedicated function before
`.has()`; a case set that varies only the key's text, always already normalized. A mutation that checks
`.has()` against the raw key instead of the normalized one stays green, because no case supplies a key
whose raw and normalized forms differ. (An exhaustive `switch` over a discriminated union's discriminant
is the same pattern on a second dimension: a case set that never exercises every union member leaves an
unreached `default`/missing-arm branch untested regardless of how many cases exist for the arms it does
cover.)

## Universality check

Independent of any local norm, project boundary, or language: the three rules describe how a test's
case set, subject, and dimensional coverage relate to a specification versus an implementation under
test, not any one language's syntax. The reproductions above are novel TypeScript constructions of the
same mechanism already reviewed and accepted for `python-coding@1.1.0->1.2.0` (PR #11) — SFL-INV-08 is
met via the deterministic, project-independent minimal reproduction limb, carried over rule-for-rule
from the already Reviewer-confirmed source observation.

## Suggested fix (delta-sized)

Mirror the `python-coding@1.2.0` `references/testing.md` §Hygiene block verbatim in structure, with the
three minimal reproductions re-expressed in TypeScript idiom (`as const` registry, upstream-filter /
downstream-overwrite serializer, normalized-`Map`-key membership test, exhaustive discriminated-union
`switch`).
