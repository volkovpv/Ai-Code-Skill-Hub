# The duplication guidance names the after-the-fact check and never the before-the-fact search

## Context (input)

An operator-triggered SFL transfer (2026-08-19; not routed through the
ordinary `WF-STATE-013` pipeline — the occasion was a direct operator audit
of a consuming project's build, argued and classified as C3-universal in
the transfer instruction itself, symmetric with a sibling skill's
transfer in the same library on the same date). `OBS-20260818-001` (Hub
PR #24, merged 2026-08-18) already recorded, for this skill, that its
duplication bullet has no backing in this stack's blocking linter and that
the advisory detector that does exist for it is blind to identifier
renaming, and separately added the union-of-callers rule for a shared
defensive routine over untrusted input to `references/security.md`. Both
of those stay correct and untouched by this one. What stayed missing,
symmetric with the same gap in a sibling skill of this library: nothing in
`## Workflow` or `## Rules` ever tells an author to search the tree, by
shape, **before** writing a new implementation — the skill teaches how to
recognize and how to safely collapse a duplicate that already exists; it
never teaches how to avoid creating one.

The evidence for the underlying pattern is already on record for this
skill: `OBS-20260818-001` measured, on one live Python codebase, one
repository-style adapter's core method byte-identical across more than a
dozen call sites introduced in over ten separate tasks (11 of 13
repository bodies byte-identical in the most affected module), and a
defensive parser standing over untrusted model output in five
independently maintained copies, each tested only against its own
caller's historical inputs — a fix applied to one copy in response to its
own caller's bug report did not propagate to a sibling copy that was
never told about it. This transfer does not re-derive that measurement; it
draws out what it implies that the prior fix did not yet act on: every one
of those copies was written by an author with no instruction to search
before writing.

## Expected behavior

A skill whose stated purpose includes low duplication and secure
collapsing of defensive routines would tell an author *when* to look for
an existing home — before the first line, by what the logic is built out
of, never by the name about to be given to the new symbol — and give a
decision order for what to do once something is found (extend it, call
it, or, past a repetition threshold, factor a parameterized home) before
ever reaching for a new file.

## Actual behavior

`references/lint-clean.md`'s duplication bullet and `references/security.md`'s
union-of-callers section both describe what is true once a shared
implementation exists or once a duplicate is found; `SKILL.md`'s
`## Workflow` opens directly at "Type strictly, name explicitly" with no
step for searching first, and no bullet in `## Rules` states a decision
order for extend-vs-call-vs-factory-vs-new-file. An author following the
skill exactly as written before this delta has every reason to write a new
module the moment a requirement arrives and no instruction to look first.

## Minimal reproduction

Deterministic, project-independent (any Python project following this
skill's stack):

1. `pricing/order.py` exports `compute_order_total(items)`, a small
   reduction over a sequence of line items.
2. A new requirement calls for the identical computation from a different
   module, `checkout/summary.py`. Following this skill's workflow exactly
   as written before this delta gives no instruction to look at
   `pricing/order.py` first — an author can satisfy every rule in
   `## Rules` (strict typing, no `Any`, lint-clean) while writing
   `derive_checkout_total` as a fresh, byte-identical-after-renaming copy,
   and both the advisory `duplicate-code` detector and the blocking linter
   stay silent, exactly as `OBS-20260818-001` already documents for this
   stack.
3. Control: with the delta below in place, the first workflow step directs
   the same author to search by shape, find `compute_order_total`, and
   either import it or extend it — no duplicate is written in the first
   place.

## Universality check

Nothing above depends on this project's rules, its stack version, or its
module layout — only on the general property that a skill's `## Workflow`
is read and followed in order, and that a workflow with no search step
gives no author a reason to look before writing. `SFL-INV-08`'s first limb
is inherited from the already-accepted measurement on `OBS-20260818-001`
(more than a dozen call sites of one adapter method across ten-plus
separate tasks, five independent copies of a defensive parser); its second
limb is met by the reproduction above, which needs no project file to run.

## Suggested fix

Add a first `## Workflow` step ("Survey before you write") and a `## Rules`
bullet stating the decision order (extend → call → factory at the third
occurrence → new file only once the search comes back empty), detailed in
a new `references/duplication-survey.md` that cross-links — rather than
restates — the existing `references/security.md` union-of-callers rule,
and is itself cross-linked from `references/lint-clean.md`'s existing
duplication bullet rather than duplicated into it.
